# دليل إعداد AATM في وضع Arena من الصفر (Ubuntu)

هذا الدليل مبني على ما نُفِّذ فعلياً عند الإعداد: المدير (`manager-0`) وأربعة موظفين (`worker-1` … `worker-4`)، كل واحد في **ملف Chrome خاص به**، يعمل عبر **Arena Agent** بسكربت Tampermonkey يتصل بالجسر المحلي `127.0.0.1:4100`. لا يحتاج الفريق إلى مفتاح API لأي نموذج.

> لا تكتب في هذا الملف ولا في Git أي قيمة حقيقية: لا رموز، ولا كلمات مرور، ولا محتوى `.env`، ولا ملفات السكربتات.

---

## 0. ملاحظة المشغّل حول موافقة Arena

- مرجع الموافقة: **ARENA-TEMP-2026-054**.
- الحد الأقصى: **4 حسابات / ملفات Arena**.
- **برومبت واحد في كل مرة** لكل ملف (يفرضه AATM أيضاً: طابور إرسال واحد، ولا يُرسَل للمدير إلا برومبت واحد في كل لحظة).
- الاستخدام: **التطوير والاختبار الداخلي فقط**.

> ⚠️ **تنبيه:** الإعداد الموصوف أدناه فيه **5 ملفات** (المدير + 4 موظفين)، وهذا **أكثر من حد الموافقة (4)**. قبل التشغيل: إما أن تُبقي 4 ملفات فقط متصلة في الوقت نفسه (مثلاً المدير + `worker-1` … `worker-3`، واترك نافذة `worker-4` مغلقة)، أو احصل على توسيع للموافقة. AATM نفسه لا يفرض حداً لعدد الملفات؛ الالتزام بالحد مسؤولية المشغّل.

## 1. التثبيت والتشغيل

```bash
cd ~/AATM
./scripts/ubuntu/install.sh        # Postgres + RabbitMQ + Redis عبر Docker (أو --sqlite)، البيئة الافتراضية، npm، Chromium
./scripts/ubuntu/start.sh          # الخادم :8000، الجسر المحلي 127.0.0.1:4100، الواجهة :5173
./scripts/ubuntu/stop.sh           # إيقاف كل ما شغّله start.sh
./scripts/ubuntu/restart.sh        # بعد تعديل .env أو تحديث الكود (--keep-frontend / --keep-bridge اختياريان)
```

### أمر واحد للتشغيل والإيقاف (الاستخدام اليومي)

```bash
~/AATM/scripts/ubuntu/start-all.sh               # بعد أي إعادة تشغيل للجهاز أو انقطاع كهرباء
~/AATM/scripts/ubuntu/stop-all.sh                # إيقاف هادئ؛ Redis وRabbitMQ يبقيان يعملان
~/AATM/scripts/ubuntu/stop-all.sh --containers   # يوقف الحاويتين أيضاً
```

- `start-all.sh` يشغّل حاويتَي Redis وRabbitMQ إن كانتا متوقفتين، ثم الخادم والجسر والواجهة والمراقب، وينتظر صحة الخدمات، ثم يفتح نوافذ Chrome للموظفين **المفعّلين فقط** (4 نوافذ كحد أقصى، بحسب موافقة Arena)، وكل نافذة تعود إلى محادثة مهمتها.
- في النهاية يطبع `AATM جاهز ✅ (N/4 متصلين)` ورابط اللوحة، أو `AATM غير جاهز ⚠️` مع ما ينقص بالضبط (مثلاً نافذة لم تتصل).
- `stop-all.sh` يغلق نوافذ AATM فقط (لا يلمس نوافذ Chrome الأخرى) دون إنهاء قسري، ويوقف الخدمات. لا يحذف أي ملف Chrome أو تسجيل دخول أو بيانات.
- لا يوجد تشغيل تلقائي عند إقلاع الجهاز: بعد إعادة التشغيل نفّذ `start-all.sh` بنفسك.

- الواجهة: `http://localhost:5173`. أول دخول: `admin@aatm.local` (أو `DEFAULT_ADMIN_EMAIL`). كلمة المرور يولّدها المثبّت في `.env` ويجب تغييرها عند أول دخول. نسيتها؟ `./scripts/ubuntu/reset-admin-password.sh`.
- **ملف `.env` واحد فقط في جذر المشروع** (`~/AATM/.env`). لا تنشئ `backend/.env`: `start.sh` يمرّر ملف الجذر إلى الخادم وإلى الجسر معاً.

### إعدادات `.env` المطلوبة لوضع Arena (الأسماء فقط)

| المتغير | الغرض |
|---|---|
| `ARENA_CONNECTOR_ENABLED` | `true` لتفعيل الموصّل (للخادم والجسر معاً) |
| `ARENA_ALLOWED_ORIGINS` | نطاق Arena المسموح (`https://arena.ai`) |
| `ARENA_BRIDGE_URL` | عنوان الجسر المحلي (`http://127.0.0.1:4100`) |
| `ARENA_BRIDGE_TOKEN` | رمز سري واحد يتشاركه الخادم والجسر — ولّده بـ `openssl rand -hex 24` ولا تضعه في Git |
| `AATM_MANAGER_PROVIDER` | `arena_agent` ليعمل المدير عبر Arena |
| `ARENA_MANAGER_MAX_EXCHANGES` | عدد التبادلات قبل بدء جلسة مدير جديدة (افتراضياً 40) |
| `ARENA_AGENT_MAX_KEEP_WORKING` | حد ضغطات Keep working (0 = بلا حد) |
| `ARENA_AGENT_NEW_SESSION_URL` | اختياري؛ فارغ = الضغط على زر New Chat |

بعد أي تعديل في `.env`: `./scripts/ubuntu/restart.sh`.

## 2. ملفات Chrome لكل موظف

كل موظف له مجلد ملف مستقل:

```bash
mkdir -p ~/.aatm-profiles/{manager,worker-1,worker-2,worker-3,worker-4}
chmod 700 ~/.aatm-profiles/*
google-chrome --user-data-dir=$HOME/.aatm-profiles/manager  https://arena.ai/agent
google-chrome --user-data-dir=$HOME/.aatm-profiles/worker-1 https://arena.ai/agent
google-chrome --user-data-dir=$HOME/.aatm-profiles/worker-2 https://arena.ai/agent
google-chrome --user-data-dir=$HOME/.aatm-profiles/worker-3 https://arena.ai/agent
google-chrome --user-data-dir=$HOME/.aatm-profiles/worker-4 https://arena.ai/agent
```

| الملف | الموظف | اسم النافذة | اللون المستخدم |
|---|---|---|---|
| `manager` | `manager-0` (المدير) | المدير | أصفر |
| `worker-1` | Backend | Worker 1 | أزرق |
| `worker-2` | Frontend | Worker 2 | أخضر |
| `worker-3` | AI Provider & Browser | Worker 3 | بنفسجي |
| `worker-4` | Orchestration & QA | Worker 4 | أحمر |

**تسمية النافذة:** الأسهل من داخل Chrome: أيقونة الملف الشخصي (أعلى اليمين) ← **تخصيص الملف الشخصي** ← الاسم واللون. (إن عدّلت ملفات `Local State` و`Default/Preferences` يدوياً فأغلق نافذة **هذا الملف فقط** أولاً، لأن Chrome يعيد كتابتهما عند الإغلاق.)

إعدادات كل ملف:
- `chrome://settings/performance`: أوقف **Memory Saver** أو أضف `arena.ai` إلى المواقع التي تبقى نشطة.
- اجعل النافذة **عريضة بما يكفي** ليظهر الشريط الجانبي وزر **New Chat** (انظر قسم الأعطال).

---

## 3. Tampermonkey في كل ملف

1. من متجر Chrome داخل الملف نفسه: **Tampermonkey** ← **إضافة إلى Chrome**.
2. افتح `chrome://extensions` ← فعّل **وضع المطوّر (Developer mode)** أعلى اليمين.
3. Tampermonkey ← **التفاصيل (Details)** ← فعّل **Allow User Scripts**. بدونه لا يعمل أي سكربت مهما ثبّتّه.

---

## 4. تسجيل الدخول إلى Arena

- **كل شخص يسجّل الدخول بحسابه الخاص بنفسه** داخل الملف المخصّص له، ويقبل **شروط Arena بنفسه**.
- AATM لا يطلب كلمات مرور ولا يسجّل الدخول ولا يقبل الشروط ولا يحل أي تحقق بشري نيابة عن أحد.
- اربط حساب GitHub من داخل Arena لملفات الموظفين (هم من يفتح طلبات الدمج). المدير لا يدفع كوداً.

---

## 5. تفعيل الموظف وتوليد السكربت

في AATM: **المتصفحات ← وكيل Arena — التشغيل الكامل**:
1. حوّل الموظف إلى **وكيل Arena** (زر «التحويل إلى وكيل Arena»). بطاقة المدير في الأعلى.
2. **إنشاء السكربت** في بطاقة الملف. الرمز يظهر **مرة واحدة فقط** ويُخزَّن تجزئته فقط.
3. احفظ السكربت محلياً (خارج المستودع):
   ```bash
   mkdir -p ~/aatm-scripts && chmod 700 ~/aatm-scripts   # مثلاً ~/aatm-scripts/worker-2.user.js بصلاحية 600
   ```

> **مهم:** كل ضغطة على «إنشاء السكربت» أو «تدوير السكربت» تُبطل السكربت القديم فوراً. ثبّت الجديد في الملف نفسه مباشرة.

## 6. تثبيت السكربت في Tampermonkey

### الطريقة أ — صفحة التثبيت
خادم مؤقت على `127.0.0.1` فقط، ثم افتح سكربت كل ملف **في ملفه هو فقط**:
```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory ~/aatm-scripts &
google-chrome --user-data-dir=$HOME/.aatm-profiles/worker-2 http://127.0.0.1:8765/worker-2.user.js
```
اضغط **Install** (أو **Reinstall/Update**)، ثم **أوقف الخادم فوراً** (`kill %1`).

> إذا ظهر السكربت كنص عادي فـ Tampermonkey لم يكن مثبّتاً عند فتح الصفحة — أو لم يُحفظ. في تجربتنا لم تحفظ صفحة التثبيت السكربت في عدة ملفات، فاستخدم الطريقة ب.

### الطريقة ب — النسخ واللصق (الطريقة التي نجحت)
1. افتح ملف السكربت كنص في ملفه:
   ```bash
   google-chrome --user-data-dir=$HOME/.aatm-profiles/worker-2 file://$HOME/aatm-scripts/worker-2.user.js
   ```
2. **Ctrl+A** ثم **Ctrl+C**.
3. أيقونة Tampermonkey ← **Create a new script…** (أو افتح السكربت الموجود من Dashboard لاستبداله) ← **Ctrl+A** ← **Ctrl+V** ← **Ctrl+S**.
4. تأكد في Dashboard أن هناك سكربتاً **واحداً فقط** باسم `aatm-arena-connector-…` ونسخته الحالية (مثلاً **2.0.1**).
5. أغلق تبويب النص (يحتوي الرمز) وأعد تحميل `arena.ai/agent`.

## 7. السماح بـ «الوصول إلى الشبكة المحلية» لـ arena.ai

صفحة arena.ai عامة، والسكربت يتصل بـ `ws://127.0.0.1:4100` على جهازك. Chrome يطلب إذناً لذلك:
- عند أول اتصال تظهر رسالة «arena.ai يريد الوصول إلى التطبيقات والخدمات على هذا الجهاز» ← **سماح**.
- إن لم تظهر: أيقونة يسار شريط العنوان ← **إعدادات الموقع** ← **الوصول إلى الشبكة المحلية** ← **سماح**، ثم أعد التحميل.

بدون هذا الإذن يُحجب الاتصال داخل المتصفح بصمت، ولا يظهر أي شيء في سجل الجسر.

---

## 8. التحقق من الاتصال واختبار المحددات

- البطاقة تصبح **متصل**، ويظهر رقم نسخة السكربت.
- **اختبار المحددات** (للقراءة فقط، لا يرسل شيئاً):

| البند | المعنى |
|---|---|
| composer / send | صندوق الكتابة وزر الإرسال — يجب أن يظهرا |
| new_session (New Chat) | زر جلسة جديدة — مطلوب لبدء كل مهمة بجلسة جديدة |
| stop / keep_working / latest_reply | طبيعي ألا تظهر على صفحة خاملة بلا محادثة |
| human_check | يجب أن يكون **none**. أي سبب هنا يوقف الملف (`needs_human`) |
| offline | يجب أن يكون **none** |
| `ok: true` | الملف جاهز |

- بطاقة المزود **Arena Agent Runtime** تصبح سليمة فقط عندما يكون ملف المدير متصلاً واختبار محدداته ناجحاً؛ وإلا تشرح السبب بالعربية.
- إذا فشل الاختبار على الصفحة الحقيقية: **لا تخمّن المحددات** — افحص الصفحة الحقيقية أولاً.

## 9. الأعطال التي واجهناها وحلولها

| المشكلة | العَرَض | السبب | الحل |
|---|---|---|---|
| **401 من الجسر** | كل الملفات «غير متصل»، و`logs/bridge.log` يُظهر `GET /v1/connector/profiles … 401` | `start.sh` كان يمرّر `.env` للجسر فقط؛ الخادم يقرأ `ARENA_BRIDGE_TOKEN` من بيئة العملية فكان يطلب بلا رمز | مُصلَح في `start.sh` (يُصدِّر `.env` للخادم أيضاً). تأكد بعد التشغيل: لا أسطر 401 في `logs/bridge.log`. لا تستخدم `backend/.env` |
| **سكربت قديم ما زال يعمل** | `connector auth failed profile=…` في سجل الجسر | Tampermonkey احتفظ بالسكربت القديم (صفحة التثبيت لم تحفظ الجديد)، أو دُوِّر السكربت من اللوحة بعد التثبيت | استبدل المحتوى بالنسخ واللصق (القسم 6-ب) وتحقق من النسخة. لا تضغط «تدوير السكربت» إلا إذا ستثبّت الجديد فوراً |
| **«terms of use» إيجابية خاطئة** | الملف يتوقف `needs_human: page shows: terms of use` فوراً حتى بعد قبول الشروط | صف روابط ثابت في Arena (`Terms of Use · Privacy Policy · Cookies`) | مُصلَح في السكربت **2.0.1**: عبارات الشروط تُحتسب فقط داخل نافذة حوار/طبقة كاملة أو بجانب زر Accept/Agree. ثبّت 2.0.1 ثم «استئناف الجلسة» |
| **New Chat مخفي** | اختبار المحددات: `new_session` غير موجود | النافذة ضيقة فانطوى الشريط الجانبي | وسّع النافذة أو افتح الشريط الجانبي، ثم أعد الاختبار |
| **الاستئناف بعد needs_human** | الملف يبقى `needs_human` بعد زوال السبب | الإيقاف لا يُرفع إلا بقرار بشري | عالج الصفحة بنفسك ثم **استئناف الجلسة** في بطاقة الموظف. إن عاد الإيقاف فوراً فالسبب ما زال ظاهراً في الصفحة |
| **`verify.sh` يمسح قاعدة البيانات الحية** | بعد تشغيل الاختبارات: الملفات «غير متصل» في AATM، ومشاريعك اختفت، وبصمات السكربتات صارت فارغة | الاختبارات كانت تستخدم `data/aatm.db` الحقيقية وتحذف كل الجداول | مُصلَح: الاختبارات تستخدم قاعدة SQLite مؤقتة دائماً (واختبار حارس يمنع العودة). إن حدث قبل الإصلاح: أوقف الخادم فقط، واستعد `data/aatm.db` من آخر نسخة احتياطية، ثم `start.sh` — الجسر يحتفظ بالبصمات في الذاكرة فتبقى النوافذ متصلة إذا طابقت النسخة |
| **عمليات vite قديمة** | المنفذ 5173 مشغول بعد `stop.sh` | ملف PID قديم فتجاهل `stop.sh` عمليات الواجهة | `pgrep -af "vite --host"` ثم أوقف عمليات `~/AATM/frontend` القديمة، و`rm -f logs/frontend.pid`، ثم `start.sh` |

أوامر تشخيص مفيدة (لا تطبع الرموز):
```bash
grep -c ' 401' logs/bridge.log                       # يجب أن يكون 0 بعد إعادة التشغيل
grep -E "connector (auth|origin|real)" logs/bridge.log | tail
ss -ltn "( sport = :4100 or sport = :8000 or sport = :5173 )"
```

## 10. فريق المشروع وإنشاء مشروع اختبار

- **فريق المشروع:** إذا احتوى إعداد المشروع على `config.team` (قائمة معرّفات موظفين، مثلاً `["worker-1"]`) فالمدير يرى هؤلاء فقط في برومبتاته ولا يقبل خطة تُسند مهمة لغيرهم (محاولة تصحيح واحدة ثم «يحتاج تدخلاً بشرياً»). بدون `team` يرى كل الموظفين المفعّلين.
- **مشروع اختبار** (مثال ما أعددناه: `oldman-088/aatm-arena-test`):
  1. أنشئ مستودعاً خاصاً جديداً مع README (من GitHub أو `gh repo create <owner>/<name> --private --add-readme`).
  2. استنسخه في مجلد مستقل خارج AATM، مثل `~/aatm-repos/<name>`. **لا تجعل المشروع يشير إلى مجلد AATM نفسه.**
  3. في **المشاريع وSDLC والذاكرة** أنشئ المشروع: `repo_path` = مسار النسخة المحلية، `repo_url` = رابط GitHub، الفرع `main`.
  4. اضبط الفريق في إعداد المشروع: `"team": ["worker-1"]`.
  5. تأكد أن المدير و`worker-1` في وضع **وكيل Arena** ومتصلان.

### أين تكتب الهدف للمدير
1. **متقدم** ← **المشاريع وSDLC والذاكرة** ← اختر المشروع ليصبح المشروع النشط.
2. **متقدم** ← **محادثة المدير** ← اكتب الهدف، ويُفضَّل أن يبدأ بـ `/goal` (مثلاً: `/goal أضف دالة hello() مع اختبار pytest`).

> شاشة **جسر القيادة** لا تحتوي حالياً على اختيار المشروع وترسل الأوامر لأقدم مشروع (`aatm-core`)، فاستخدم **محادثة المدير** لمشروع الاختبار.

المدير يرد بخطة، والمهام تُرسَل لجلسة `worker-1` في Arena، وطلب الدمج يراجعه المدير، و**الدمج لا يتم إلا بموافقتك** في مركز الموافقات.

## 11. النسخ الاحتياطي والاستعادة

```bash
# نسخة من بيانات AATM (قاعدة البيانات، مساحات العمل، .env) — داخل backups/ المستبعَد من Git
./scripts/ubuntu/backup.sh
./scripts/ubuntu/restore.sh backups/<archive>.tar.gz && ./scripts/ubuntu/verify.sh

# نسخة كاملة للمشروع بدون التبعيات
mkdir -p ~/aatm-backups
tar czf ~/aatm-backups/AATM-$(date +%F-%H%M).tar.gz \
  --exclude=node_modules --exclude=.venv --exclude=frontend/dist -C ~ AATM

# ملفات Chrome والسكربتات (تحتوي تسجيلات الدخول والرموز) — أغلق نوافذ Chrome أولاً لنسخة متسقة
tar czf ~/aatm-backups/profiles-$(date +%F-%H%M).tar.gz -C ~ .aatm-profiles aatm-scripts
chmod 600 ~/aatm-backups/*

# الاستعادة
tar xzf ~/aatm-backups/AATM-<stamp>.tar.gz -C ~
tar xzf ~/aatm-backups/profiles-<stamp>.tar.gz -C ~
cd ~/AATM && ./scripts/ubuntu/install.sh && ./scripts/ubuntu/start.sh
```

النسخ الاحتياطية تحتوي `.env` وتسجيلات دخول Arena والرموز: احفظها بصلاحية `600`، ولا ترفعها إلى Git أو أي خدمة.

## 12. المراقب (Watchdog)

مراقب خفيف **للقراءة فقط**: لا يعيد تشغيل أي شيء ولا يغيّر ولا يصلح أي شيء، بل ينبّهك فقط.

- يبدأ تلقائياً في الخلفية مع `scripts/ubuntu/start.sh` ويتوقف مع `scripts/ubuntu/stop.sh` (ملف PID: `logs/watchdog.pid`). لتعطيله: `WATCHDOG_AUTOSTART=false scripts/ubuntu/start.sh`.
- كل 60 ثانية (`WATCHDOG_INTERVAL`) يتحقق من: صحة الخادم الخلفي `/api/health`، الجسر على 4100، الواجهة على 5173، حاويتي `aatm-redis` و`aatm-rabbitmq`، حالة كل ملف Arena (انقطاع الاتصال أو `needs_human` مع السبب)، الأسطر الجديدة في `logs/backend.log` و`logs/bridge.log` التي تحتوي Traceback أو ERROR أو 401 أو 500 أو فشل التنسيق، وأي مهمة بلا تقدم لأكثر من 20 دقيقة.
- كل مشكلة جديدة تظهر كإشعار سطح مكتب بعنوان «AATM — تنبيه» وتُسجَّل مع الوقت في `logs/watchdog.log`. لا يتكرر التنبيه نفسه أكثر من مرة كل 10 دقائق، ويصلك إشعار واحد «عاد للعمل» عند زوال المشكلة.
- رمز الجسر يُقرأ من `.env` ولا يُطبع أبداً.

```bash
scripts/ubuntu/watchdog.sh --test-notify   # إشعار تجريبي
scripts/ubuntu/watchdog.sh --once          # دورة فحص واحدة
tail -f logs/watchdog.log                  # متابعة التنبيهات
```

إذا لم تظهر الإشعارات فتأكد أن `start.sh` شُغّل من جلسة سطح المكتب (وليس عبر SSH) وأن `notify-send` مثبت (`sudo apt install libnotify-bin`).

## 13. تنبيهات تيليجرام (اختيارية)

الخدمة ترسل فقط: لا تستقبل أوامر، ولا تستخدم webhook، ولا تفتح أي منفذ، ولا ترسل الرموز أو كلمات المرور أو قيم `.env` أو فروقات الكود.

1. افتح محادثة مع `@BotFather` في تيليجرام، وأرسل `/newbot`، واتبع الخطوات، واحتفظ بالرمز الذي يعطيك إياه.
2. افتح محادثة مع البوت الجديد واضغط Start، ثم أرسل له أي رسالة.
3. لمعرفة رقم محادثتك افتح هذا الرابط في متصفحك بعد وضع رمزك مكان `<TOKEN>`، وخذ الرقم من `"chat":{"id":...}`:
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
4. أضف إلى ملف `.env` (ولا تضعها في Git):
   ```
   TELEGRAM_BOT_ENABLED=true
   TELEGRAM_BOT_TOKEN=<الرمز>
   TELEGRAM_ALLOWED_CHAT_IDS=<رقم المحادثة>
   ```
   لعدة محادثات افصل الأرقام بفاصلة.
5. شغّل `scripts/ubuntu/stop-all.sh` ثم `scripts/ubuntu/start-all.sh`. سجل الخدمة في `logs/telegram.log`.

تصلك رسالة عند: حاجة نافذة إليك وعند عودتها للعمل، وطلب دمج ينتظر موافقتك، وانتهاء مهمة أو مشروع أو فشلهما، وجاهزية AATM بعد التشغيل أو ما ينقصها، وتنبيهات المراقب الحرجة. إذا بقي الفحص البشري مفتوحاً 10 دقائق يصلك تذكير واحد، ولا يتكرر التنبيه نفسه أكثر من مرة كل 10 دقائق.


### التشغيل التلقائي بعد تسجيل الدخول

لتفعيل خدمة systemd الخاصة بالمستخدم (بدون صلاحيات root):

```bash
./scripts/ubuntu/install-autostart.sh
systemctl --user status aatm.service
# للإلغاء دون إيقاف العمليات الحالية:
./scripts/ubuntu/uninstall-autostart.sh
```

تُشغّل الخدمة `start-all.sh` بعد تسجيل الدخول وترتّب نفسها بعد `network-online.target`.
يعتمد توفر الشبكة فعلياً على إعداد systemd والشبكة في الجهاز؛ إذا لم تتوفر الشبكة
عند تسجيل الدخول، تأكد منها ثم شغّل الأمر يدوياً. تحتاج نوافذ Chrome إلى جلسة سطح مكتب.

### تسجيل دخول المدير من الطرفية

```bash
./scripts/ubuntu/admin-login.sh admin@example.com
```

يُطلب إدخال كلمة المرور دون إظهارها ولا تُحفظ. يُحفظ الرمز وتاريخ انتهائه في
`~/.config/aatm/admin-token.json` بصلاحيات `0600`؛ احمِ هذا الملف واحذفه عند عدم الحاجة.
يمكن تحديد الخادم بـ `--url` والملف بـ `--token-file`. يتطلب الخادم غير المحلي HTTPS.
عند إعادة تعيين كلمة المرور، تُحدّث قاعدة البيانات فقط ولا يُعدّل ملف `.env`.
